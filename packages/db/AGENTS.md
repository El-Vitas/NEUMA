# AGENTS.md — DB

> Database package conventions. Inherits all standards from `AGENTS.md` at the repo root.
> Design decisions: `docs/architecture/adr/010-adopt-prisma-orm-8.md` and `021-everything-is-a-block.md`.

## Stack

- Prisma ORM 8 (`prisma` CLI + `@prisma/orm-postgres`), PostgreSQL 18
- TypeScript strict
- bun

## Contract

The data model is the Prisma 8 **contract**: one `.prisma` file per model and per enum, under `prisma/models` and
`prisma/enums`. Every file starts with `// use prisma-8`; a file without that line is silently ignored.

### Naming

| Type | Pattern | Examples |
|---|---|---|
| Model | `{entity}.model.prisma` | `user.model.prisma` |
| Enum | `{name}.enum.prisma` | `user-role.enum.prisma` |
| Seed | `{domain}.seed.ts` | `users.seed.ts` |

### Rules

- **One model per file, one enum per file.**
- **Enums are `native_enum`** with explicit values, and fields use `pg.enum(Name)`, so they stay PostgreSQL enum types.
- **Dates are `TimestamptzJsDate`** (a `timestamptz` read as a JS `Date`); `updatedAt` is `temporal.updatedAtJsDate()`.
- **Ids are `String @default(uuid(7))`**, generated by the application.
- **Uniqueness is `@@unique`** (a constraint), so `upsert({ conflictOn })` can use it. `@@index(..., unique: true)` only
  for a partial or expression index.
- **Constraint and index names are explicit (`map:`)** and match the database exactly.
- **What the contract cannot model lives in SQL inside a migration**: generated `tsvector` columns, index operator
  classes (`gin_trgm_ops`), extensions and functions. Document it on the model.

## Changing the schema

1. Edit the contract.
2. `bun run db:generate` (`prisma contract emit`) writes `src/contract/contract.json` and `contract.d.ts`.
3. `bun run db:migrate -- --name <name>` (`prisma migration plan`) writes `migrations/app/<timestamp>_<name>/`.
4. Read `migration.ts`. Anything that converts or moves data, or would lose it (drops, type changes, NOT NULL),
   is edited by hand; recompile with `node migrations/app/<dir>/migration.ts` from this folder.
5. `bunx prisma migration check` must pass. Commit the migration folder, its snapshot and `migrations/app/refs/db.json`.

`db migrate` runs destructive operations without asking, so review step 4 before anyone applies it.

## Applying migrations

- `bun run db:migrate:deploy` runs `scripts/migrate-deploy.ts`: it adopts a database Prisma 7 created (`db sign` at the
  baseline, refused unless the schema matches exactly) and then applies what is pending. It reads
  `MIGRATION_DATABASE_URL`, or `DATABASE_URL` when that is unset. The migrate image runs the same script.
- `bun run db:verify` checks the live database against the contract.

## Client

- `createNeumaDatabase(url)` in `src/client.ts` builds the client. One per process: it owns the pool; close it on shutdown.
- `src/index.ts` is the package's public API: the client factory, `NeumaDatabase` / `NeumaTransaction`, the enum
  constants (value and type share a name), `isUniqueViolation`, the JSON types, and re-exported Prisma helpers
  (`and`, `or`, `not`, `Scalars`, `Shape`, `ResultType`, `Models`).
- The emitted contract under `src/contract/` is committed and never edited by hand.

## Seeds

- **One file per domain** in `prisma/seed/`, plus `main.seed.ts` as the entry point (`bun run db:seed`).
- **Idempotent.** Each seed checks for existing data before inserting.
- **Deterministic.** Seed the same data every time — no random values in seed scripts.
- **Shaped like the app writes it.** A page is a `Block` row of type `page` that lists its paragraph and its subpages
  in `children`; text carries its `text` and Yjs `textState`, mentions get their `BlockLink`, and the space lists its
  top-level pages in `rootPageIds`. Fixed ids and a fixed Yjs client id keep every run identical. There are no outbox
  events: search and backlinks read the blocks directly (ADR 022).
