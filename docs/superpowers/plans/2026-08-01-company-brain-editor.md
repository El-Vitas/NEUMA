# Company Brain Editor Implementation Plan

> **For agentic workers:** Use the slice-squad workflow. Agents must not spawn agents, commit, push, or edit files outside their assigned scope.

**Goal:** Replace the foundation textarea with a validated ProseMirror document model and a maintainable portal editor while preserving page versions and future search extraction.

**Architecture:** ProseMirror owns the browser editor state and serializes a versioned document JSON contract. `packages/shared` owns the contract schema and types. The portal owns the React `EditorView` lifecycle and UI commands. The backend validates the same contract before persistence and continues creating immutable page versions.

**Tech Stack:** Bun, React 19, Next.js 16, ProseMirror model/state/view/schema, PostgreSQL JSON persistence, Zod, Bun tests.

---

## Scope

This round implements the editor foundation and basic rich text only. It does not implement Yjs/Hocuspocus collaboration, comments, databases, attachments, embeds, slash commands, semantic search, or full block coverage.

## Required ProseMirror Contract

The persisted shape must follow ProseMirror JSON, not HTML and not a custom parallel block format:

```json
{
  "type": "doc",
  "content": [
    {
      "type": "paragraph",
      "content": [{ "type": "text", "text": "Example" }]
    }
  ]
}
```

The shared schema must bound:

- Root node type `doc`.
- Paragraph, heading, bullet list, ordered list, list item, blockquote, and code block nodes.
- Text nodes with a maximum length.
- Heading levels from 1 to 3.
- Strong, emphasis, code, and link marks with validated URLs.
- Maximum node depth and total node count.
- No raw HTML or unknown node/mark types.

The schema version remains explicit so future migrations can add nodes without silently accepting incompatible documents.

## React Lifecycle Requirements

- Create `EditorState` from the validated document in a client boundary.
- Create `EditorView` only after the mount element exists.
- Apply transactions in `dispatchTransaction` and expose serialized JSON through a controlled callback.
- Destroy `EditorView` on unmount or page replacement.
- Never create an `EditorView` during server rendering.
- Do not use `useEffect` for API calls; lifecycle cleanup is the legitimate use of an effect.
- Keep commands and schema definitions outside the component file.
- Keep the component focused on composition, state wiring, and rendering.

## TDD Requirements

- Write shared schema tests first and verify they fail before implementation.
- Test valid documents, invalid node types, invalid marks, oversized content, bad links, and schema version mismatch.
- Test ProseMirror serialization/deserialization helpers independently of React.
- Test editor component behavior for initial content, transaction updates, read-only state, and cleanup.
- Test backend rejection of invalid content and successful version creation for valid content.

## Verification Gate

- Run `bun install` after dependency changes.
- Run shared, portal, and backend focused tests.
- Run full backend and portal test suites.
- Run `bun run check` with zero code warnings/errors.
- Run `bun run build`.
- Run Prisma generate/validate if backend types or page DTOs change.
- Read every changed file after each slice and run a final consolidation pass for duplicate schemas, adapters, constants, and content extraction logic.
